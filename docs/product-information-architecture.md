# Reservation System 產品資訊架構（M1）

> 更新日期：2026-08-11  
> 狀態：本次產品重整的實作契約  
> 上位規則：`AGENTS.md`、`clinic-booking-spec-v3.md`、`docs/product-restructure-baseline.md`

## 1. 產品原則

1. 顧客與品牌成員先看到「現在要完成的工作」，再看到設定與技術模組。
2. v3 標準功能可由品牌自行啟用；未啟用功能不佔用日常導覽。
3. 模組啟用、公開發布、外部渠道就緒是三個不同狀態，不可用單一 boolean 混用。
4. 角色限制必須同時存在於導覽、頁面 server guard、查詢條件與 RLS，不能只藏按鈕。
5. 系統管理者總控台與品牌營運後台維持獨立殼層。
6. 所有顧客入口保留品牌 context；任何 query string 都不能直接成為租戶授權依據。

## 2. 目標導覽

| 工作區 | 首要任務 | 子入口 |
|---|---|---|
| 今日工作台 | 處理今天需要行動的工作 | 今日預約、待確認、待付款、候補、報到、通知失敗、未讀訊息 |
| 預約營運 | 管理時間制與場次制預約 | 日曆、預約清單、預約候補 |
| 活動與報名 | 管理活動生命週期與現場作業 | 活動與場次、報名名單、活動候補、QR 報到 |
| 顧客與會員 | 管理顧客關係與標準會員能力 | 顧客、互動時間軸、會員／套票、會員等級、分眾／自動化 |
| 訊息中心 | 處理對話、素材與投遞 | LINE 客服、訊息素材、自動回覆、投遞狀態 |
| 報表 | 依已啟用模組查看營運結果 | 預約、報名、未到、候補、付款、會員、CRM |
| 設定中心 | 完成品牌上線與治理 | 品牌、服務／資源、排程、入口、LINE／LIFF、Rich Menu、通知／付款、網域、團隊、稽核 |

桌面側欄只顯示上述七個一級入口；子入口在工作區首頁或展開區呈現。行動版維持相同資訊順序，不另造一套導覽。

## 3. 身分與權限工作流

產品管理身份只有系統管理者與品牌管理者。系統員工、品牌員工不是第三種管理身份，而是由對應管理者逐項授權的工作帳號。

| 工作區／能力 | 品牌管理者 | 品牌員工：品牌管理 | 品牌員工：營運操作 | 品牌員工：指定服務提供者 |
|---|:---:|:---:|:---:|:---:|
| 今日工作台 | 全品牌與上線狀態 | 全品牌營運 | 今日營運待辦 | 僅指派行程 |
| 預約營運 | 管理 | 管理 | 建立與管理 | 查看指派行程；僅完成／未到 |
| 活動與報名 | 管理 | 管理 | 報名、候補、報到 | 預設不顯示 |
| 顧客資料 | 完整 | 完整 | 必要營運資料 | 僅指派服務必要資料 |
| 會員／套票 | 管理 | 管理 | 查詢與標準核銷 | 不顯示 |
| CRM 自動化 | 管理 | 管理 | 不顯示 | 不顯示 |
| 訊息中心 | 全部 | 全部 | 客服對話 | 不顯示 |
| 報表 | 全部 | 全部 | 營運摘要，不含密鑰或不必要 PII | 不顯示 |
| 設定中心 | 全部 | 依授權 | 不顯示 | 不顯示 |
| 團隊／治理 | 全部 | 不顯示 | 不顯示 | 不顯示 |

未知身分或權限必須 fail closed，不得自動取得營運寫入權。資料庫舊角色值僅作 RLS 相容映射。

### 3.1 角色首頁

- **品牌管理者**：上線完成度、渠道／付款阻擋、今日營運、趨勢與人員權限。
- **具品牌管理權限員工**：今日待辦、異常、容量與被授權設定。
- **具營運操作權限員工**：今日預約、報到、候補、待付款與未讀訊息。
- **具指定服務提供者權限員工**：我的今日行程、下一位顧客、可執行的完成／未到操作。

## 4. 標準模組啟用契約

M2 需要在 `clinic_settings` 增加設定驅動的產品模組欄位；這些欄位只控制品牌是否使用標準能力，不是收費 entitlement：

| 建議欄位 | 預設 | 控制範圍 | 不可取代 |
|---|---:|---|---|
| `events_enabled` | `false` | 活動與報名工作區、顧客活動入口 | `public_registration_enabled` |
| `memberships_enabled` | `false` | 會員／套票後台與顧客入口 | 個別方案 `active` |
| `crm_automation_enabled` | `false` | 分眾與三種規則式自動化 | 顧客資料與互動時間軸 |
| `line_channel_enabled` | `false` | LINE 客服、Rich Menu 與 LINE 通知就緒流程 | 實際 token／destination／LIFF 驗證結果 |

預約營運與顧客核心不設成可移除模組；`public_booking_enabled` 只控制顧客公開預約。Email 使用現有 `email_enabled`，但仍須另判斷 server provider 是否就緒。

### 4.1 三層狀態

每個可選模組必須能區分：

1. **未啟用**：不出現在日常導覽，品牌管理者或具品牌管理權限員工可從設定中心啟用。
2. **已啟用但未就緒**：出現在啟用中心，顯示缺少的設定；不可對外發布。
3. **已就緒／已發布**：可在日常工作區及顧客入口使用。

## 5. 頁面狀態契約

所有重整頁面必須明確處理：

| 狀態 | 必要行為 |
|---|---|
| 空白 | 說明第一個可執行動作，不顯示沒有上下文的空表格。 |
| 未啟用 | 說明此功能屬標準功能，由品牌管理者或具品牌管理權限員工前往設定中心啟用。 |
| 未就緒 | 列出缺少設定與阻擋原因，不把外部憑證缺少當成程式錯誤。 |
| 停用 | 保留歷史資料可查，但禁止建立新的公開交易。 |
| 權限不足 | 不載入不必要資料，回到角色首頁並顯示可理解訊息。 |
| 外部失敗 | 保留目前有效狀態，寫入錯誤紀錄並提供安全重試。 |

## 6. 新品牌七步啟用中心

| 步驟 | 完成判定 | 警告或阻擋 |
|---|---|---|
| 1. 品牌資料 | 名稱、slug、公開聯絡資訊與品牌識別存在 | slug 衝突或品牌停用為阻擋 |
| 2. 服務／活動 | 至少一個有效服務；啟用活動時至少一個可用活動／場次 | 沒有可公開項目為阻擋 |
| 3. 人員／資源／排班 | 服務有可用的人員排程或 service/resource 排程 | 沒有容量來源為阻擋 |
| 4. 預約與報名規則 | 模式、前置時間、取消／改期與公開開關有效 | 設定不相容為阻擋 |
| 5. LINE／LIFF／Rich Menu | destination、token mapping、Login Channel、LIFF、webhook 與已發布 menu 均通過檢查 | 缺密鑰、provider/channel 不一致或發布失敗為阻擋 |
| 6. 通知與付款 | 啟用的渠道有 provider；需要收款時有測試成功紀錄 | 缺 provider 或 webhook 驗證為阻擋 |
| 7. 正式上線測試 | 公開入口、預約／報名、通知、權限與回復測試完成 | 外部證據缺失時只能標示「測試環境就緒」 |

就緒狀態必須由 server 依實際資料與部署設定計算，不得由前端勾選冒充完成。

## 7. 統一顧客入口與深連結契約

統一 LIFF 入口以品牌 scope 為前提，M5 實作下列 view：

| view | 顧客任務 | 模組條件 |
|---|---|---|
| `home` | 顯示品牌可用服務入口 | 無 |
| `book` | 立即預約 | `public_booking_enabled=true` |
| `appointments` | 我的預約、取消與改期 | 已驗證顧客身分 |
| `events` | 活動／課程 | `events_enabled=true` 且 `public_registration_enabled=true` |
| `tickets` | 我的報名與票券 QR | `events_enabled=true` 且已驗證顧客身分 |
| `membership` | 會員、套票、剩餘堂數與優惠 | `memberships_enabled=true` 且已驗證顧客身分 |
| `chat` | LINE 客服 | `line_channel_enabled=true` 且渠道就緒 |
| `brand` | 品牌資訊 | 無 |

推薦 canonical URI：`/book?clinic_slug={slug}&view={view}`。server 仍必須以已驗證 LINE ID token、瀏覽器 token、hostname 或資料庫關聯決定租戶，不採信任意 `clinic_id`。

## 8. Rich Menu 產品契約

### 第一批必做

- 預約型、活動型、綜合型三套模板。
- 每格有 `label`、action、目標與可測試深連結。
- 真實圖片、點擊區域與手機預覽。
- 草稿、LINE 驗證、發布、版本、錯誤與回復。
- 發布失敗保留目前線上版本。
- `legacy_progress_enabled=false` 時不提供 progress action。
- 依模組啟用狀態替換或停用無效按鈕。

### 第二批優化

- Rich Menu Alias 頁籤切換。
- 顯示期間／排程。
- 區域曝光、點擊與預約／報名轉換。
- 模板複製與歷史比較。

依單一顧客狀態切換、A/B 測試、大量分眾與跨渠道廣告受眾不屬本次必做。
