# XINHOW 產品介面準則 v2

## 適用範圍

這份準則同時約束系統管理後台、品牌營運後台、LINE 互動訊息與三種 DEMO 形象頁。它取代以大卡片、漸層、模糊背景和通用藍色按鈕堆疊出的介面做法。

## 方向

- 後台是工作台，不是宣傳頁。優先使用表格、狀態列、分隔線與欄位對齊。
- 同一畫面只保留一個主要動作；其他動作使用有邊框的次要按鈕或文字連結。
- 系統管理使用灰白畫布、深綠黑導覽與高密度資料列，不使用玻璃效果或漂浮卡片。
- LINE 互動依「觸發事件 → 顧客看到的內容 → 顧客下一步 → 投遞狀態」排列。
- 形象頁以產業內容建立版式：美業是編輯型療程索引、線上課程是課綱型目錄、皮拉提斯是課表型工作板，不共用同一張 Hero 卡片。

## 字體

- 產品介面與正文：`Chiron Hei HK Variable`（昭源黑體），200–900。
- 美業標題與敘事段落：`Chiron Sung HK Variable`（昭源宋體），200–900。
- 英文展示字：各產業原有的 Manrope、Montserrat 等拉丁字型；繁中一律回到昭源字體，不再回退到 Noto。
- 資料、編號與金額：系統等寬字型並啟用 tabular figures。
- 正文桌面 14–16px、手機至少 16px；輔助文字不得小於 12px；行高 1.5–1.75。

## 密度與版面

- 間距採 4／8px 節奏；畫面區段主要使用 16／24／32px。
- 後台最大寬度 1600px，桌面側欄 224px；資訊以 2 欄或 3 欄整合，避免單一簡短欄位被拉滿整列。
- 狀態摘要使用連續資料帶，不拆成多張圓角卡。
- 手機將資料列重排成標題、狀態與內容，不讓整張表格橫向溢出。

## 元件

- 面板圓角 3–4px，按鈕與輸入框 4px；不用 12–24px 的通用 SaaS 大圓角。
- 所有可操作控制必須是 `button`、`a`、`input`、`select` 或 `summary`，並有明確文字與可見焦點。
- 圖示使用同一套 1.8px 線性 SVG；裝飾圖示加 `aria-hidden`，圖示按鈕必須有可讀名稱。
- 狀態不可只靠顏色；同時顯示「已完成、待處理、失敗」等文字。

## LINE 訊息

- 訊息卡上方依序顯示品牌、中文狀態、任務標題，不使用大面積色塊與英文 badge。
- 詳情欄位使用左側標籤、右側實際值；日期包含星期與台北時間。
- 主要按鈕只處理當下任務，例如立即付款、接受名額、開啟票券；次要動作不得搶過主要動作。
- 後台預覽必須與實際 Flex Message 使用相同閱讀順序。

## 驗收尺寸

- 375px、768px、1024px、1440px。
- 需檢查鍵盤焦點、44px 觸控範圍、無橫向捲動、200% 文字縮放與 `prefers-reduced-motion`。

## 參考流程

本準則由 UI UX Pro Max 的高密度企業工作台、Swiss／Minimal 工具介面、資訊表格、狀態語意與 Next.js 響應式規則篩選後整理；已排除第一次搜尋回傳、但不符合本產品的 Glassmorphism、Hero＋CTA 與 Soft UI 建議。
