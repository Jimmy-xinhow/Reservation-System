# 統一顧客入口與深連結契約

更新日期：2026-09-14
適用版本：產品重整 M2 起；2026-09 顧客中心整合

## 目的

所有 LINE Rich Menu、歡迎訊息、通知及品牌網站入口，必須使用同一組品牌深連結語意。入口只描述顧客要完成的任務，不直接耦合後台頁面或資料表名稱。

## 標準入口

| key | 顧客名稱 | LIFF view | 瀏覽器備援 | 啟用條件 |
|---|---|---|---|---|
| `home` | 服務首頁 | `home` | `/` | 永遠可用 |
| `booking` | 立即預約 | `booking` | `/book/browser` | `public_booking_enabled` |
| `appointments` | 我的預約 | `appointments` | `/my` | 預約模組可用 |
| `events` | 活動／課程 | `events` | `/register` | `events_enabled` 且 `public_registration_enabled` |
| `tickets` | 我的票券 | `tickets` | `/my` | `events_enabled` |
| `membership` | 會員／套票 | `membership` | `/membership` | `memberships_enabled` |
| `support` | LINE 客服 | `support` | `/`（品牌聯絡資訊） | `line_channel_enabled` |
| `brand` | 品牌資訊 | `brand` | `/` | 永遠可用 |

Rich Menu 的內建功能固定使用 `postback`，由 webhook 在 LINE 內先完成導覽、查詢或選擇；只有複雜表單才產生 `https://liff.line.me/{brand_liff_id}?clinic_slug={slug}&view={view}&task=1`。一般瀏覽器 URL 以品牌公開 origin 加上備援路徑及 `clinic_slug`。自訂 HTTPS 連結仍可直接使用 URI。若品牌採獨立渠道，禁止回退其他品牌或全域 LIFF ID。

LINE 第一次導向 LIFF Endpoint 時，會暫時把永久連結的額外 query 放在 `liff.state`，等 `liff.init()` 完成後才還原。顧客入口在初始化品牌設定前必須唯讀解析 `liff.state` 內的 `clinic_slug`／`view`，不可先套用全域預設品牌，也不可改寫或刪除任何 `liff.*` 參數。

程式中的唯一來源是 `lib/customer-entry.ts`；Rich Menu、webhook 與顧客中心不得各自維護另一份路徑表。

## 身分與租戶規則

1. URL 的 `clinic_slug` 只用於解析公開品牌，不代表已授權。
2. LIFF ID token 必須用該品牌解析出的 LINE Login Channel ID 向 LINE 驗證。
3. 驗證後的 `sub` 仍須在 `clinic_id` 範圍內尋找顧客，不可跨品牌共用查詢結果。
4. 瀏覽器備援 token 必須包含並比對 `clinicId`。
5. 未啟用領域不產生按鈕；直接存取時 server route 仍須拒絕。
6. 未綁定顧客可在 LINE 會員頁輸入姓名、電話與生日完成綁定；server 必須先以目前品牌的 Login Channel 驗證 ID token，再於同一 `clinic_id` 內比對／建立顧客，禁止跨品牌或覆蓋其他 LINE 帳號。
7. LINE 主流程使用官方 Account Linking：Messaging API 取得的 link token 不落庫，只保存 10 分鐘 nonce 雜湊；完成事件仍以 webhook destination 限定品牌。
8. 解除綁定只清除目前 `clinic_id` 的顧客／報名 LINE 關聯，並移除個人 Rich Menu，不影響其他品牌。

## 狀態與相容界線

- M2 已完成入口 key、品牌參數、LIFF view、瀏覽器備援及模組條件契約。
- M5 已由 `/book` 統一解讀八個 `view`；現有 `tab=my`／`tab=chat` 仍保留相容。
- 2026-09 起，未指定 `view` 時先顯示服務首頁，集中呈現目前已啟用的預約、活動、票券、會員、客服與品牌捷徑；停用的模組不會出現在首頁或導覽列。
- 活動 LIFF 報名會把品牌驗證後的 ID token 送到 server；票券與會員依該 LINE 身分下的已綁定顧客切換，不跨品牌共用。
- 暫停新增預約不會隱藏「我的預約」；暫停公開活動列表不會隱藏既有票券。
- Rich Menu 只有在目標 view、模組狀態、圖片與 LINE 渠道驗證全部通過後才可發布。
- `task=1` 的 LIFF 不顯示八宮格導覽；預約／候補／報名完成且不需付款時提供「完成並回到 LINE」。
- 預約原生流程為「選服務 → 選日期 → 聚焦 LIFF 選時段及必要資料」；活動卡片直接開啟指定活動，不再先進活動總表。
- `legacy_progress_enabled=false` 時，入口集合永遠不包含舊版服務進度。

## 商用完善第一批：LINE 到瀏覽器備援

- 備援路徑沿用 `CUSTOMER_ENTRY_DEFINITIONS`，禁止另建 view 路徑對照表。
- 預約備援保留品牌、`service_id`、`doctor_id`、`date` 及來源參數；兩種預約模式使用相同日期承接，並重新查詢即時空位，不承接舊名額或舊價格。
- LINE 與瀏覽器均只承接真實存在且介於台北當日與品牌最長預約日期內的日期。服務／人員仍必須存在於目前品牌公開設定；日期不是訂位授權，最短前置時間與容量仍由 server 驗證。
- 活動備援保留 `event` 與既有私密活動邀請 `access_token`；該 token 僅供活動存取，不代表顧客登入。其他 view 不帶活動邀請。
- 備援不轉送 ID token、LINE user ID、瀏覽器身分 token、付款 token、姓名電話、任意 redirect 或 `liff.*`。瀏覽器依既有品牌身分流程操作。
- 此批保留的是入口選擇，不是已輸入的個資草稿；任務中途切換裝置的草稿恢復另列後續驗收。
- 回歸命令：`npm run test:customer-entry`；`npm test` 同時執行既有契約查核與入口行為測試。

## 第二批：網站與登入返回

- `loadPublicBrandPage` 為服務／活動產生指定項目的 `href`，品牌頁所有正式模板共用 `LiveBrandPage`，不再把所有服務導向同一個未選擇的總入口。
- 網站行動使用該品牌的渠道設定。LINE 未啟用、缺 LIFF／Login Channel 或設定讀取失敗時，保留本品牌瀏覽器入口。讀取失敗不是品牌已通過 LINE 驗證。
- `useLiff` 必須等待 `liff.init()` 完成才執行登入，並明確指定當前 URL 為 `redirectUri`；不能先清除 `liff.*`，也不能把 SDK 預設返回 Endpoint 當作已保存任務。
- 初次導向的頂層 `access_token` 不得作為活動邀請轉送。存在 `liff.state` 時，邀請只能從該原始任務 query 取得。
- 付款結果只根據 server 查詢結果顯示，不採信返回網址 `state`。處理中採有限次數輪詢並提供重查及目標紀錄入口；不以重查動作重新建單。

## 共用頁首及完成後返回

- 頁首預設「線上服務」；只有 caller 的 SDK 環境判定可顯示「LINE 內開啟」。不得用頁面位置或 LINE 設定存在推導身分已驗證，也不得顯示固定「安全連線」。
- `ReturnToLineButton` 統一預約、候補、改期及報名完成後關窗。保留現有付款完成等顯示條件，不因關窗而新增或修改交易。
- `tryCloseLiffWindow` 對不支援及 SDK 拋錯回傳 false；true 僅代表呼叫已送出。按下後頁面若未關閉，保留手動關閉提示與既有查詢紀錄連結。

## 人員選擇與瀏覽器切換 LINE

- 新增預約在 LIFF 與瀏覽器共用 `bookingDoctorSelection`：可指定人員保留合法選擇、資源型服務不帶人員、必選人員僅於唯一選項自動帶入。服務實際可用時段與人員適用範圍仍由 server 驗證。
- 更換人員會重新查時段，不清空服務表單、加購或系列次數；更換服務才重設這些服務相關資料。
- `bookingLiffHandoffUrl` 只攜帶品牌、來源及目前服務／人員／日期／首次再次類型；空選擇刪除舊 query。姓名電話、身分憑證、表單答案不放網址。LIFF 與瀏覽器均承接合法的 `visit_type`。
- LIFF 改期後返回目前品牌的 `view=appointments`，不重新開始預約。

## 時段查詢與再次預約

- 服務、人員、日期、加購或預約類型改變時，舊時段及候補選取失效。清空必要條件也必須清空結果，不得只跳過查詢。
- LINE 入口的舊請求須取消，且即使舊 promise 仍返回，也不得更新結果、錯誤或載入狀態。交易名額仍由 server 原子驗證。
- 再次預約的明確選擇優先於初次入口 query；不能因設定較晚載入而覆蓋。既有加購／套票／表單答案不自動沿用到新的一筆預約。
- 再次預約使用原預約的 `patient_id`，只在重新驗證的 LINE 綁定名單內承接；不存在時留空並提示選擇，不以姓名比對或自動替換成第一位顧客。ID 不放進入口網址，server 仍須驗證預約對象。
- 已停用／不可用服務的舊 ID 必須清除並提示；即使可用服務列表為空，也不能把該筆再次預約當成舊版免選服務預約。選擇有效服務或明確重新開始後才解除限制。
- 綁定查詢的舊回應不得覆蓋最新名單或消耗待承接的原顧客；既有選擇被移除時，提交就緒條件必須失效。
- LINE 與瀏覽器改期採相同的時段取消規則與人員選擇規則；不可用服務／人員不能僅憑舊 ID 通過前端就緒檢查。查詢中或尚未選取新時段時禁止送出，server 仍原子驗證名額與授權。
- 改期入口的 LINE 登入失敗導向瀏覽器「我的預約」完成該入口身分驗證，不能冒用 LINE 身分，也不能將顧客帶到建立新預約。

## 預約紀錄的操作回饋

- 取消、候補與前往付款使用同頁共用的即時操作鎖，避免重新渲染前或不同卡片的重複提交；此鎖不取代 server 冪等與授權檢查。
- 只有 server 回應成功才移除已取消預約／已處理候補，並顯示成功提示。後續列表重查失敗須保留已確認結果與其他列表內容，提供重新整理；不可把查詢失敗顯示成沒有預約。
- 操作開始使先前列表請求失效；舊回應不得把已取消紀錄加回。請求失敗可以重試；付款表單送出後保留操作鎖直至離開頁面，建立付款失敗才解鎖。

## 瀏覽器身分恢復

- 紀錄查詢的 401／403 回應清除目前頁面身分與可見紀錄，重開驗證表單；500／網路錯誤不能當成身分失效。錯誤判定使用 HTTP 狀態，不比對訊息文字。
- 清除儲存憑證須比對失效值，保護其他品牌及其他分頁寫入的新憑證。無法存取 localStorage 時，仍可在目前頁面重新驗證。
- 重新驗證不自動重送交易；驗證成功後只重新查詢目前品牌紀錄。

## 報名付款恢復

- 單筆報名儲存資料損壞不能阻止獨立讀取品牌瀏覽器憑證；無儲存能力時可手動提供報到憑證。
- 付款建立成功後才合併保存非空報到憑證，保留既有報名欄位；使用瀏覽器憑證付款不寫入空的報到憑證。
- 同頁付款使用即時鎖，建立失敗可重試；提供帶品牌的「我的紀錄」入口查看狀態，不自動重建付款。

## 報名查詢

- 電話與報名編號只由 POST JSON body 傳送，查詢網址僅保留品牌。GET 不再回傳個資，舊頁面須重新載入。
- 保留速率限制與 server 品牌解析；查詢仍需符合品牌、報名編號及電話，成功回應禁止快取。
- 修改條件清空舊結果並取消舊請求；舊成功／失敗回應不得更新新查詢。離開頁面亦取消查詢。

## 報名取消

- 只有 HTTP／API 成功且明確回傳 cancelled 才顯示已取消；其他回應不可推論取消完成。
- 同頁取消以即時鎖避免連點，送出期間不可更改憑證。失敗保留憑證供重試，成功才清空；切換憑證清除舊提示。
- 提供同品牌「我的紀錄」入口。此操作不自動退款，沿用 server 的品牌授權、狀態與通知規則。

## 我的紀錄 Portal

- 暫時讀取失敗保留紀錄並提供重查，只有 401／403 才清除目前身分與資料；重新驗證導向同品牌的查詢驗證入口。
- 取消以明確 cancelled 回應更新狀態並保留成功提示，即使重查失敗也不得恢復取消按鈕或待付款操作。付款入口要求報名與付款狀態皆為 pending。
- 操作鎖與舊查詢隔離僅改善前端操作，server 的授權、交易冪等與名額驗證仍須獨立驗收。

## 會員與套票

- 本機憑證存在不代表已驗證；伺服器查詢成功後才開放購買。查詢中不得購買，跨方案購買共用即時鎖。
- 網路錯誤保留套票與方案供重查，401／403 才清除身分。更換顧客清空資料並使舊請求失效，避免恢復上一位顧客。
- 付款建立失敗解鎖，表單送出後保持鎖定；不因重查自動建立付款。

## 報名提交

- 提交函式再次檢查活動場次／票種、姓名電話、必填欄位與 LINE 身分；不能只靠停用按鈕。必填文字不得只含空白。
- 送出期間固定表單，成功後保持提交鎖，失敗保留資料；同頁鎖不取代 server 的重複報名及名額規則。
- 成功頁付款僅對待付款報名開放；金流客戶返回路徑保留品牌與報名 ID，回到付款恢復頁，不重開活動報名表。

## 預約與候補提交

- LINE 與瀏覽器送出使用即時鎖並停用表單；失敗保留資料，成功保持鎖定直到明確開始下一筆。
- LINE 送出函式要求完整就緒條件；訂金付款要求 pending 狀態且同頁只能有一筆建立請求進行。
- 此為前端重複操作保護，網路逾時不代表交易未建立；server 冪等、重查與跨裝置交易仍需獨立驗收。

## 改期提交與付款返回

- 兩入口改期以即時鎖和停用表單保護提交，成功後保持鎖定，失敗保留條件供重試。
- 改期訂金以結果中的 appointment_id 建立付款，pending 狀態才可執行；金流客戶返回同品牌「我的預約」，不重新開啟改期表單。

## 顧客建立輸入

- LINE 與瀏覽器建立身分共用姓名／電話／生日型別及長度檢查，生日必須是真實日期；無效輸入在呼叫資料庫與 LINE 前回傳 400。
- LINE ID token 要求非空字串，隨後仍須通過 server 的品牌渠道驗證。既有 SQL 顧客重用與電話人數上限不變。
