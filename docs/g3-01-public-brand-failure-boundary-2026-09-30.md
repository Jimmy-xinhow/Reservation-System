# G3-01 公開品牌不符與資料庫故障分流

狀態：**本機候選；staging 同版回測前，G3-01 仍待驗證。**

- 修補前 staging 品牌網域 `booking-qa.laihowke.com`：正確品牌的 `/api/booking/config` 回 200；不屬於該網域的品牌代號在 `/api/booking/config` 與 `/api/registration/events` 都回 500。沒有回傳其他品牌資料，但把客戶端不符誤記為服務故障。
- 共用品牌解析器原本把 Supabase 查詢錯誤和真正查無／網域不符都壓成 `null`，公開路由因此無法安全分辨。候選讓查詢故障拋出不含資料的錯誤，而查無或網域不符仍回 `null`；21 個公開預約、報名、付款、聊天入口把真正查無改為 404。既有 route catch 對查詢故障仍回 500。
- 本機行為測試證實「網域查詢失敗拋錯」、「品牌不符回 404」及「資料庫故障回 500」；公開品牌邊界 5/5、相關錯誤與付款入口 37/37、contracts、typecheck、build 通過。尚未把這些本機結果計為主驗收。
- staging 後續只需以同版公開網址定向核對：正確品牌 200、外品牌／不存在品牌 404 且無 PII；資料庫故障分支維持本機受控測試，不對共享 staging 注入故障。本批不建立顧客或付款測資。
