# XINHOW 管理者交付檢查單

版本：2026-08-13。適用於系統管理者將新品牌交付給品牌管理者。每一項須填寫實際結果與證據時間，不可用「已啟用」代替外部實測。

## 1. 系統管理者交付前

- [ ] 品牌名稱、slug、聯絡資料與啟用狀態正確。
- [ ] 第一位品牌管理者已建立並完成登入；未在文件或訊息中留下初始密碼。
- [ ] 新品牌已自動建立 `clinic_settings`，時間制／場次制、預約前置、最長可約日、電話多人與首次時長均已確認。
- [ ] 套餐與加購狀態只代表合約／合作狀態；未交付功能不得標示已上線。
- [ ] 系統員工僅套用工作所需權限範本，沒有取得完整系統管理者權限。
- [ ] 平台「品牌觀察」只選入已取得試用同意的真實品牌；QA fixture 不計入三品牌樣本。

## 2. 品牌管理者啟用

- [ ] 服務或活動已建立；服務預約目標與產業情境一致。
- [ ] 人員、場地或設備已建立且啟用；資源型服務沒有虛構人員。
- [ ] 同日多段排程、例外日期、容量、服務時長、加購時長已從顧客入口驗證。
- [ ] CSV 匯入先預覽再確認；保留匯入工作、成功／失敗列與來源檔案雜湊。
- [ ] 品牌員工以櫃檯、服務提供者、行銷或財務檢視範本起始，再依工作微調。
- [ ] 預約自訂欄位、必填同意、重複預約上限與快速再約已依品牌政策確認。
- [ ] 交班待辦已建立負責人、到期日、狀態與必要篩選。
- [ ] 公開預約／報名在資料與排程完成後才開啟。

## 3. 外部渠道

- [ ] 渠道測試中心已執行，LINE、LIFF、Email、金流與公開入口分開保存結果。
- [ ] LINE destination、Login Channel ID、LIFF ID、endpoint path 與渠道驗證完成。
- [ ] LINE secret／access token 只存在 server environment；品牌資料庫不保存明文機密。
- [ ] Rich Menu 圖片、逐格動作、無障礙標籤、手機 LINE 顯示、發布與回復已實測。
- [ ] Email 寄件網域與實際測試信已驗證；未完成時保持停用。
- [ ] 綠界／藍新測試付款、回呼重送、付款狀態與逾時釋放已驗證；未完成時不開正式收款。
- [ ] 平台短網址可解析正確品牌；自訂網域另驗證 DNS、HTTPS 與 host spoof 拒絕。

## 4. 交付 smoke test

- [ ] 桌機與手機各完成一次顧客預約。
- [ ] 時間制與場次制依品牌設定顯示正確。
- [ ] 自訂欄位、同意、加購、重複預約、確認通知與我的預約可使用。
- [ ] 取消與改期保留歷史；額滿候補與釋出名額流程正確。
- [ ] 品牌管理者可完成設定；品牌員工直接輸入未授權網址仍被 server guard 拒絕。
- [ ] 系統管理者、系統員工、品牌管理者、品牌員工的桌機／手機導覽與權限均驗收。
- [ ] 報表來源轉換、預約完成率、通知失敗與匯出品牌範圍正確。

## 5. 試用觀察與加購決策

- [ ] 三個真實試用品牌均已同意觀察並開始產生操作事件。
- [ ] 每品牌記錄首次可預約時間、設定頁退出率、權限求助數與預約完成率。
- [ ] 每個加購收集 `positive`、`neutral`、`negative` 或 `won`，並保存理由。
- [ ] 至少兩個品牌為 `positive`／`won` 才建議進入報價；三品牌資料齊全但不足兩個則暫緩。
- [ ] 雙向行事曆、退款對帳、POS／庫存／分潤、多語與白牌均未因畫面出現而被誤認為已交付。
